# ParkStop

Peer-to-peer parking for Indian cities. People list an empty driveway or bay;
drivers nearby book it, navigate to it in-app, and pay when they leave.

- `backend/` — Express + Prisma + Postgres, deployed on Railway
- `frontend/` — Expo / React Native (Android), expo-router
- `web-demo/` — untracked, deliberately

## Ground rules

- **Personal documents are gitignored and must never be committed.** Aadhaar and
  PAN scans, signed forms, payment-setup notes.
- **Secrets live in Railway variables.** Never in the repo, never pasted into a
  chat. `.env.example` lists the names only.
- Edit the project files directly and show the diff. Do not hand back code to
  paste by hand.
- Verify a fix before calling it done. Run it, print the numbers, show the
  before and after. Do not re-solve something already fixed.
- Plain English in replies. Short sentences.

## Deploys and the database

`npm start` is `npx prisma migrate deploy && node src/server.js`.

**Never put `prisma db push` back into `start`.** On 6 Nov 2026 it refused to
add a unique constraint without `--accept-data-loss`, exited non-zero, and the
`&&` meant the server never started. The backend was down until the index was
created by hand. `migrate deploy` never prompts, which is the point.

Schema changes: edit `prisma/schema.prisma`, run
`npm run migrate:create -- --name what_changed`, read the generated SQL, commit
the schema **and** the migration folder together. See
`backend/prisma/migrations/README.md`.

## How the money works

Read these before touching anything that moves money.

- **`PaymentService.computePayable` is the single definition of what a driver
  owes**: `total_price + advance_fee - amount_paid`, plus arrears. The order
  route, the QR route and the checkout screen all call it. Do not reimplement it.
- **`total_price` is parking alone.** The advance fee is a separate column and
  is never folded in.
- **`BookingRefundPolicy` holds every money rule as pure functions** — no
  database, no gateway — so they can be tested exhaustively. `BookingRefundService`
  moves the money and does no arithmetic of its own. If a figure is wrong, the
  bug is in the policy module.
- **One payout per booking.** `payouts.booking_id` is UNIQUE, and
  `processBookingPayout` locks the booking row, checks for an existing payout,
  and writes the row and the wallet credit in one transaction.
- **An owner is never credited before the money is in.** Settlement requires
  `payment_status === 'paid'`.
- **Owner payouts are manual.** The owner requests, the balance moves out of
  their wallet, an admin sends a bank transfer and records the UTR. RazorpayX
  automatic payouts are not approved for ParkStop — the code for them was
  deleted on purpose, do not add it back.
- **Payout bank accounts are set in exactly one place**: `verifyBank`, after
  Cashfree confirms the account and matches the name to their Aadhaar. Locked
  after approval. Never add another write path to `users.bank_account_number`.
- Payment is normally taken at checkout. The owner's QR screen can also take it
  mid-session, so any code that assumes "unpaid until the end" is wrong.

## Things that will catch you out

- `frontend/android/` is gitignored and regenerated by prebuild. **`app.json` is
  the source of truth** for permissions and config. Editing the manifest does
  nothing lasting.
- `ACCESS_BACKGROUND_LOCATION`, `RECORD_AUDIO` and `SYSTEM_ALERT_WINDOW` are in
  `blockedPermissions` on purpose. Background location in particular would
  trigger a mandatory Google review.
- Navigation uses **Google Routes API**, not OSRM and not Ola. Ola is the map
  tile provider and a fallback for geocoding. The Google key is locked to the
  app with `X-Android-Package` and `X-Android-Cert`, so the signing SHA-1,
  `EXPO_PUBLIC_ANDROID_CERT_SHA1` and the Cloud Console restriction must all
  agree or navigation 403s.
- Map markers are PNGs generated at runtime by `frontend/utils/markerBitmap.ts`,
  in pure JS. react-native-maps mis-sizes custom-view markers on the new
  architecture. Changing a marker needs only a Metro reload, not a rebuild.
- Auth is **Firebase ID tokens**, verified server-side. ParkStop issues no JWTs
  of its own. There is also an OTP session gate: the backend stores Firebase
  `auth_time` and only accepts tokens from a verified sign-in.
- A spot is invisible in the finder unless its owner's `verification_status`
  is `'approved'`. It defaults to NULL. `backend/scripts/approve-owner.js`
  diagnoses and fixes this for one account.
- `backend/node_modules` was copied from Windows at one point. If anything says
  `node.exe: not found`, run `rm -rf node_modules && npm install`.
